ERROR REPORTING
------------------------------------------------------------------------------
* fs/sock try methods do not break on usage errors other than EINVAL and EBADF
so usage errors come up as I/O errors (retriable).

* fs/sock try methods don't close the file/socket on error.

* f/sock try methods return string errors (can do `err == 'not_found'` though!).

* file:try_close() is made with protect_io() so it returns I/O errors!

* pbuffer:try_skip() is made with protect_io() so it returns I/O and protocol errors!

* pbuffer:try_have() etc. is considered I/O so it returns string errors.

* structured errors are complicated:
	- go back to string errors with a prefix for selective catching and
	decision to retry and/or close the file/socket?

* raising and non-raising functions are inconsistent:
	* try_*() functions return plain strings and don't close the file/socket.
	* unprotect_io() converts all string errors to i/o errors.
		* result: raise tbl_err but return nil,str_err, but then protect_io()
		returns nil,tbl_err. also now it's tostring(err) == 'access_denied'
		cuz we don't know if it's str_err or tbl_err.

* error reporting lacking context:
	- unprotect_io() lacks the context that functions with check() have.
	- sometimes even check() lacks context because it's inside try_() code.
* check() from errors.lua is ungreppable because of all local check() flavors.
* check_errno() is not raising like all other check*() functions.
